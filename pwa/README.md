# TBYB · TETO / Comparison platform edition 04

직접 비교하고 나의 기준으로 고르는 플랫폼의 소개 웹사이트와 PWA 앱. 첫 데모는 Air와 14형 Pro 비교팩입니다. 일정만 요청하고, 경험 기록은 써본 뒤 선택합니다. 요금·기간·제휴·리워드 금액을 확정하지 않은 기기 로컬 시연 제품입니다. [v2 디자인 결정과 리워드 경계](DESIGN_V2.md).

[v3 소개 페이지 디자인과 문구 변경](DESIGN_V3.md): 수평 비교팩, Air·Pro 색과 기기 디테일, 고운바탕 화면 문구, 공감 영역, 비교 노트 로고. 폰트·그림을 자체 호스팅하고 오프라인 캐시에 포함합니다.

[v4 선택된 플랫폼 로고와 상호 검토 개선](DESIGN_V4.md): 웹·앱·PWA 공통 심볼, 첫 비교팩과 확장 구상 분리, 모바일 탐색과 명시적 구매 기기 선택.

[v5 기기 형상과 다크 로고 보정](DESIGN_V5.md): 공식 상판 사진을 참고한 키 배열·트랙패드·스피커 타공, 개폐 홈, 두 색을 유지하는 다크 로고.

[v6 기기 그림의 투시와 정렬 보정](DESIGN_V6.md): 한 카메라에서 투영한 화면·상판·하판, 대칭 스피커, 면에 맞는 타공과 키 각인.

[v7 스피커 그릴 보정](DESIGN_V7.md): 넓은 타공 영역, 작고 균일한 구멍 간격, 실제 표시 크기에서 자연스러운 그릴 질감.

[v8 실제 표시 경계 보정](DESIGN_V8.md): SVG 키보드에 남아 있던 HTML용 사다리꼴 클리핑 충돌 제거, 화면에 실제로 그려진 경계 검사.

## 실행

Node.js 22 이상에서:

```sh
npm ci
npm run dev
```

- 웹사이트: http://127.0.0.1:4317/
- 체험 앱: http://127.0.0.1:4317/app/
- 운영 시뮬레이터: http://127.0.0.1:4317/app/studio/

배포(통합, 2026-10-01): 웹사이트는 `web/`(MIKU), 앱은 이 PWA입니다. 앱에 필요한 파일은 모두 `public/app/`에 있고 경로는 모듈 기준 상대 경로라서 `npm run build` 후 `dist/app/`을 그대로 `https://ajs-bit.github.io/tbyb-mvp-miku/app/`에 올리면 앱은 `/app/`, 운영 시뮬레이터는 `/app/studio/`에서 열립니다. 서비스워커 범위는 앱 폴더로 한정되어 웹 페이지를 제어·캐시하지 않습니다. `public/index.html`은 로컬 확인용 예전 소개 페이지입니다.

웹과 같은 출처에서 열리므로 화면 테마는 웹과 같은 `tbyb-miku-theme` 키를 씁니다(예전 `tbyb-teto-theme` 값은 공용 키가 없을 때 한 번 복사). 웹의 `tbyb-miku-demo-v2`에 대기 중인 요청이 있으면 앱 첫 화면의 일정 양식에 희망 시작일을 미리 채웁니다(읽기 전용, 웹 기록은 쓰지 않음). 앱 기록 키 `tbyb-teto-demo-v1`은 그대로입니다.

앱에서 **체험 중인 화면 둘러보기**를 누르면 경험 기록부터 확인할 수 있습니다. 전체 과정을 보려면 웹에서 **데모 일정 요청**을 저장한 다음 운영 시뮬레이터에서 확인 단계를 진행합니다. 기존 데모가 있다면 이전 기록 그대로 이어집니다. 운영 화면에서 내보내기·초기화를 할 수 있습니다.

## 구현 범위

- 웹: 소개, 비교팩, 미확정 상업 조건, 데모 일정 요청, 운영 시뮬레이터.
- 앱: 내 체험 상태와 다음 행동, 일상 장면의 선택형 경험 기록 누적, 선택·확신·이유, 반납 준비, 7일·30일 후속 결과 입력.
- 기록: 용도 사전 조사 없음. 차이 없음·불편함·모르겠음도 유효하며 자유 글은 선택. 작성 중 단계 복원, 동일 날짜·동일 답 중복 저장 차단. 기록 없이도 선택·반납 가능. 기존 상세 시간·점수 기록은 펼쳐보기로 보존.
- 리워드: 반납 검수 완료 후 체험당 1회 검토 신청, 추가 확인/검토 완료와 사유 이력. 실제 인증·지급 없음. 금액은 `null`, 화면은 금액 미정. 클라이언트 로컬 상태는 실제 사용 증명이나 부정 방지 수단이 아님.
- 상태: 요청 → 운영 확인 → 두 기기 확보 → 결제 대기 → 데모 거래 대조 → 확정 → 인계 → 체험 → 반납 접수 → 실제 회수 확인 → 기기별 검수 → 완료.
- 판매: 구매 의향과 판매 확인을 분리. 한 대 판매를 확인해도 나머지 기기·부속품 회수와 검수를 완료해야 종료.
- 취소: 인계 전만 허용, 링크 차단·진행 중 거래 확인 요구. 환불 요청과 환불 완료 분리.
- 저장: 동일 출처·기기·브라우저의 localStorage. 탭 간 상태 갱신, 새로고침 복원, 원본 JSON 내보내기. 손상된 데이터는 자동 삭제하거나 덮어쓰지 않음.
- PWA: manifest, 192/512 PNG 아이콘, service worker 캐시. 최초 연결 뒤 화면·기록의 오프라인 사용. 브라우저별 실제 설치 및 iOS/Android 실기기 QA는 별도.
- 화면 테마: 웹·앱·운영 상단에서 **기기 설정 / 라이트 / 다크** 선택. 기본은 기기 설정을 실시간으로 따릅니다. 같은 브라우저의 선택을 기억하며 다른 탭에도 반영합니다. 테마를 바꿔도 작성 중인 폼과 체험 기록은 유지합니다. 저장이 막혀 있으면 현재 화면에만 적용하고 안내합니다.

## 검증

```sh
npm test
npm run build
npx playwright install chromium --only-shell
npx playwright test
node scripts/verify-theme.mjs
```

상태·기록·리워드 테스트와 브라우저 전체 시나리오: 날짜만 요청, 작성 중 복원, 부정/모름 답, 반복 기록, 저장 실패, 리워드 검토, 기록 없이 반납, 기존 구매·회수·검수 여정, 320/390/768px 앱, 데스크톱, 손상 저장소 보존, 오프라인 재접속. `artifacts/`에 화면과 실패 근거가 생성됩니다.

전체 브라우저 시나리오는 라이트·다크 기기 설정으로 각각 실행합니다. 테마 검사에는 첫 렌더 전 적용, 설정 저장 실패, 탭 간 변경, 미저장 입력 보존, 오프라인 설정 복원을 포함합니다. `verify-theme.mjs`는 실행 중인 로컬 서버에서 주요 다크 화면과 선택·저장·대화상자의 텍스트 대비 및 넘침을 검사하고 `artifacts/theme/`에 화면과 JSON을 저장합니다. 장식용 그림·비활성 컨트롤은 대비 검사에서 제외하며 전체 접근성 인증을 뜻하지 않습니다.

설치형 PWA의 실행 전 스플래시 색은 정적 manifest 값입니다. 화면 내부의 테마 선택과 달리 OS의 시작 화면 색까지 변경하지 않으며, 실기기의 시작 화면은 별도 확인이 필요합니다.

## 경계

실제 예약·결제·SMS·인증·재고 연동·고객 서버가 없습니다. 운영 화면은 권한 제어를 흉내 내지 않는 **로컬 시뮬레이터**입니다. 앱은 PWA이며 네이티브 APK/IPA가 아닙니다. 동일 브라우저 밖으로 기록이 동기화되지 않습니다. 한 번에 한 건의 체험만 시뮬레이션하며 연속 예약·다중 재고 관리는 범위 밖입니다. 기기별 다음 대여 가능/차단을 운영 보드에 표시합니다. v2 경험 기록은 누적하며, v1 상세 시간·점수 기록만 기기별 최신 한 개를 유지합니다. 배포 경로는 하위 경로(`/tbyb-mvp-miku/app/`)에서도 동작하며 `e2e/base-path.spec.mjs`가 `scripts/serve-pages.mjs`로 확인합니다. 체크박스는 실제 삭제·거래·반납의 증빙이 아닙니다.

가격·기간·매장·사양·계약 주체·취소/환불 조건은 실제 유료 운영 전에 확정해야 합니다. 배포본도 같은 시연 범위입니다.
