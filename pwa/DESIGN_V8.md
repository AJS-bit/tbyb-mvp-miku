# 화면에 실제로 그려진 기기 경계

2026-09-30 MSG 요청 `3fe394406459e654128ad0279aa7e1f06a5961700b4531f225c34b42debddfe4`. 타공 밀도보다 스피커의 투시 방향과 원근이 어긋나 보이는 문제를 다시 점검했다.

## 재현된 오류

`public/styles.css`의 예전 HTML용 `.keyboard`에는 `clip-path:polygon(4% 0,96% 0,100% 100%,0 100%)`가 있었다. `public/visuals.mjs`의 SVG 그룹도 같은 클래스여서 이미 투영한 키보드를 다른 사다리꼴로 다시 잘랐다. Pro에서는 키보드 홈의 양 옆 경계가 스피커·상판과 달라졌고, Air에서는 바깥 키가 잘렸다. 확대 렌더링에서 해당 CSS만 끄면 차이가 재현된다.

v6/v7 검사는 SVG 경로의 좌표, 소실점, `getBBox()`와 `isPointInFill()`만 읽었다. 이 값들은 상위 그룹의 CSS 클리핑 이후 실제로 보이는 윤곽을 보증하지 않는다. 기존의 투시 검증 완료 표현은 이 범위를 넘어섰다.

## 수정과 확인

- SVG 그룹을 전용 `.device-keyboard`로 분리하여 HTML용 자르기 스타일이 적용되지 않게 한다.
- 스피커의 밀도·배치와 공유 카메라 좌표는 유지한다. 스피커만 다른 방향으로 돌려 다른 불일치를 만들지 않는다.
- 새 브라우저 회귀 검사는 키캡·홈 내부의 경계 표본을 화면 좌표로 옮겨 `elementFromPoint()`로 실제로 그려졌는지 확인한다. 수정 전 라이트·다크 모두 Air 바깥 키에서 실패를 재현했다.
- 상판·그릴·키보드·트랙패드의 깊이 방향, 가까워질 때 구멍 크기와 간격의 증가, 화면·힌지·앞쪽 홈, 히어로와 비교팩의 실제 CSS 및 모바일·다크 표시를 함께 검토한다.
- 서비스워커는 v11로 갱신한다. 이전 캐시에서 업데이트할 때 기록을 보존하고 새 그림을 오프라인에서도 읽는지 별도로 확인한다.
