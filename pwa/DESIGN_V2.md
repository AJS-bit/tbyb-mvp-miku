## 바뀐 경험

일정만 요청 → 평소처럼 사용 → 써본 장면을 선택해 기록 → 내 선택·반납 → 반납 검수 후 리워드 검토 신청.

- 처음 요청할 때 작업 종류·비교 포인트·기기 선호·확신을 묻지 않는다. 미응답을 특정 용도·확신 점수로 만들지 않는다.
- 영상·웹 서핑, 문서·공부, 들고 다니기, 그냥 써보기 중 실제 해본 장면을 고른다. 기록은 전부 선택이며 기록 없이 결정·반납할 수 있다.
- 3단계 선택형 입력. 써본 기기와 비교 조건 → 느낌과 순간 → 앞선 답변에 맞춘 후속 질문. 최소 글자 수 없음. 자유 글은 선택.
- 차이 없음·불편함·모르겠음도 정상 기록이다. 서로 다른 장면의 응답을 평균내거나 우열 점수로 만들지 않는다.
- 경험은 추가 저장되며 기존 시간·점수 기록도 보존한다. 작성 중 단계와 답변은 동일 브라우저에서 복원한다. v1 저장 키를 유지하며 읽기 시 자동 초기화하지 않는다.

## 리워드의 경계

1,000원은 사용자 예시이며 확정 데이터가 아니다. 화면은 **금액 미정**, 저장값은 `null`이다. 로컬 데모에서 실제 신청·인증·지급은 발생하지 않는다.

구현한 흐름:

- 체험 인계 전 기록 작성 차단.
- 같은 날의 동일한 선택 조합 재저장 차단. 글만 늘려도 통과하지 않는다. 다른 날에 같은 감상을 남기는 것은 허용한다.
- 비교 조건이 다름, 한 기기만 사용, 선호와 다음 선택이 다름은 추가 맥락 확인 대상으로 남긴다. 자동 거절하지 않는다.
- 반납·검수 완료 후 체험 ID당 신청 한 건. 신청 당시 포함된 기록 ID를 보존하므로 이후 기록 추가로 검토 대상이 조용히 바뀌지 않는다.
- 운영 시뮬레이터에서 추가 확인 또는 검토 완료를 사유와 함께 누적한다. 검토 완료는 지급 완료가 아니다.

실제 부정 방지를 위해 필요한 별도 구현:

- 인증된 사용자·서버 발급 대여 ID·실제 출고·회수 이력 연결. 브라우저의 플래그나 화면 코드만으로 사용을 증명했다고 처리하지 않는다.
- 데이터베이스의 대여별 유일한 지급 키, 원자적 지급 처리, 재시도 멱등성, 취소·환불 연계.
- 변경 이력이 남는 검토·표본 확인 및 사용자 설명·이의 제기 경로. 문장 길이·속도·긍정 여부로 자동 지급/거절 금지.
- 실제 고객 데이터로 오탐과 누락을 확인한 뒤 조건 확정. 한 사람의 무작위 응답을 완벽히 판별한다고 주장하지 않는다.

사용 기기의 스크린 타임·개인 파일·브라우저 기록을 요구하지 않는다. 실제 운영 정책 및 경제성이 검증된 것은 아니다.

## 버전 1 운영 규칙 유지

두 기기 확보 → 거래 대조 → 예약 확정, 구매 의향과 판매 확인 분리, 한 대 판매 후 나머지 회수·검수, 검수 전 재대여 차단, 저장 실패 시 성공 표시 금지는 유지했다. 종전의 '예약 전에 용도를 정한다'는 기획만 새 사용자 피드백에 따라 변경했다.
